Card Interaction Patterns

Exploring how users open sessions, dismiss cards, and access artifacts. Each pattern is shown as an interactive demo — hover over the cards to see the behavior.

A — Clickable card surface + hover X to dismiss

Entire card is the primary action (opens session). Dismiss X appears on hover in the top-right corner. Artifact button sits inline and stops event propagation.

Used by: Linear, GitHub notifications, Slack messages, Apple Mail

+ Largest hit target + Clean at rest - Dismiss hidden until hover

B — Hover action bar (floating)

No buttons visible at rest — card is pure content. On hover, a floating action bar appears in the top-right with all available actions. Card itself is not clickable.

Used by: Notion pages list, Figma file browser, Vercel deployments

+ Cleanest resting state + All actions equal weight - Requires hover (touch unfriendly) - Actions invisible until discovered

Recommendation

Pattern A or D are the strongest fits here. The card's primary job is to take you to the session — making the entire surface clickable (like Linear's issue cards or GitHub's notification rows) gives maximum affordance with minimum chrome. Dismiss is secondary and infrequent, so hiding it behind hover (A) or showing it subtly (D) keeps the feed clean.

The current footer approach (C) is the safest for discoverability, but in a feed of 5-10 cards, the repeated button rows create visual weight that competes with the content. Pattern A eliminates that — the card IS the button.

Key insight: the artifact button already demonstrates the right pattern — it's an inline interactive element inside content. "Open session" should follow the same logic: the card surface itself, not a labeled button inside it.
