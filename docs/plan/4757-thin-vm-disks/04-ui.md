# 04 — UI: storage-full dialog; no disk sizes for vm

**Depends on:** 03-api-usage-refusal
**Part of:** VM disks grow inside the user's storage pool — see [README](./README.md)

## Context

The user sees why a create was refused and what to do, and no screen names a disk size for a vm agent.

## Implementation plan

Apply `/react-ui-engineering`.

1. `packages/ui/src/modules/agents/`: on a create error with `data.storageFull` (from `useCreateAgent` in `api/mutations.ts`, the inline create, the default-agent create and the kit apply), show a dialog with the use and the three fixes; "Request more" uses `links.computeRequest`.
2. `components/migration-plan-summary.tsx`: replace "Its disk is resized to X" with "It shares your agents' storage."
   Remove `storageSize`/`storageResized` from `RuntimeMigrationPlanView` in api-server-api `view.ts` and `types.ts` and from the api-server mapper.
3. `starter-kits/views/starter-kit-view.tsx`: hide the disk size when the agent will run as a vm.

## Acceptance criteria

- [ ] A create at ≥90% shows the dialog with the figures and fixes, and no agent appears.
- [ ] The migration plan names no disk size; a vm kit shows none.

## Smoke test

`mise run //packages/ui:check`, `mise run //packages/ui:test`, `mise run //packages/api-server-api:check`, `mise run //packages/e2e/playwright:check`.
