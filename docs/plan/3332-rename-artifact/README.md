# Rename an artifact from the library

> Working plan — temporary, committed on the feature branch. Deleted once the feature ships.

**Issue:** https://github.com/dam-agents/dam/issues/3332

## Goal

A user renames an artifact they own, in place, from the row menu in the Artifacts
library and from the Artifacts section in the chat sidebar. A small dialog holds the
new title. The share link, the version history and the view count do not change.

Today the row menu offers Share, Download and Delete only. To rename, the user must
ask an agent, which needs a sandbox, a session and the right words. Wrong titles stay
wrong, and long titles stay unreadable where the UI truncates them.

## Approach

**The feature is UI-only.** The backend already renames: `artifactLibrary.update`
accepts `title`
([`router.ts`](../../../packages/api-server-api/src/modules/artifact-library/router.ts)),
and a title-only patch writes one column — no version bump, no new slug, no view-count
change
([`artifact-library-service.ts`](../../../packages/api-server/src/modules/artifact-library/services/artifact-library-service.ts)).
The [artifact-library architecture page](../../architecture/artifact-library.md) already
records the intent: an artifact's kind is settled at create, while "Title and file name
stay editable". No contract change, no schema change, no doc change.

The UI work adds one dialog and wires it into the shared row menu:

- **One dialog component**, modelled on the existing
  [`folder-dialog.tsx`](../../../packages/ui/src/modules/artifacts/components/folder-dialog.tsx):
  a `Modal` with a single Title field and a Save action.
- **One menu item** in
  [`artifact-row-menu-items.tsx`](../../../packages/ui/src/modules/artifacts/components/artifact-row-menu-items.tsx),
  the component both the library rows and the chat sidebar rows already render.
- **The dialog is hosted by the parent**, reached through an `onRename` callback. This
  mirrors how `onShare` already works, and it is necessary: a dialog rendered inside
  `DropdownMenuContent` unmounts when the menu closes on select.

### Decisions taken

| Question (from the issue) | Decision | Why |
|---|---|---|
| Title only, or file name too? | **Title only.** | Every user story describes the display title. The file name only surfaces in the download and in search. The API supports `fileName`, so it stays a cheap follow-up. |
| Inline edit, or a dialog? | **Dialog.** | Three surfaces share one menu component. The chat sidebar row is 32 px tall and truncates hard, so inline editing there is cramped. `FolderDialog` already gives the exact shape. |
| Who may rename? | **The owner, for every artifact in their library — agent-published included.** | Settled by the code, not open. The library is owner-scoped, `update` is gated by `manageAgentsProcedure`, and no per-artifact author check exists in the module. |

### Surfaces

`ArtifactRowMenuItems` renders in two components, which cover three places:

- [`artifact-row.tsx`](../../../packages/ui/src/modules/artifacts/components/artifact-row.tsx)
  — used by the **Artifacts library page** (through `FolderGroup` and
  `ExperimentsSection`) and by the **sandbox home Artifacts section**.
- [`chat-artifacts-panel.tsx`](../../../packages/ui/src/modules/artifacts/components/chat-artifacts-panel.tsx)
  — the **chat sidebar**.

The docked artifact panel beside the conversation keeps its header as it is. It has no
overflow menu today, and the issue does not ask for one.

### One defect to fix along the way

`useUpdateArtifact` invalidates `list`, `listFolders`, `getContent` and `preview`, but
not `get`
([`mutations.ts`](../../../packages/ui/src/modules/artifacts/api/mutations.ts)). Both the
docked artifact panel and the chat link chip read `get`, so without this fix they keep
showing the old title after a rename.

## Conventions & glossary

- **Title** — the display name shown in the library, the chat sidebar and the share page
  banner. This is what rename edits. Max 300 characters (`titleSchema`).
- **File name** — a separate value, used for the download name and matched by library
  search. Out of scope here.
- **Slug** — the unguessable share-link key. Independent of the title, and never
  regenerated by an update.
- Apply the **`/react-ui-engineering`** skill while implementing — the change is entirely
  in `packages/ui`.
- No new tests. Verification is the existing suite plus a manual smoke test. The repo
  bans code comments.

## Out of scope

- Renaming the **file name** — the API supports it, but no user story asks for it.
- **Moving an artifact into a folder** — that is
  [#3231](https://github.com/dam-agents/dam/issues/3231), a separate action in the same
  menu. This plan leaves the menu easy to extend for it.
- A rename control in the **docked artifact panel** header or the **preview dialog**.
