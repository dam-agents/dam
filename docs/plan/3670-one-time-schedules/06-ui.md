# 06 — UI

**Depends on:** 01-once-spec-and-fire-path, 02-delivery-outcome-and-retention, 03-schedule-once-session-type
**Part of:** One-time tasks — see [README](./README.md)

## Context

Users create and watch one-time tasks on the existing Schedules tab: the create form gains a **Repeat / Once** switch (Once offers **Now** or a date + time + timezone), the list separates what will still happen from a collapsed **Past** section of completed one-time tasks with their outcome and Session link, and the hard-stop warning counts only schedules that will still fire. No shortcut from chat in v1. Apply **/react-ui-engineering**.

## Implementation plan

1. **Types & API** — `packages/ui/src/types.ts` `Schedule` (l.174-197): `type: "cron" | "rrule" | "once"`, `at?`, keep `timezone`. `modules/schedules/api/mutations.ts` (l.10-60): `useCreateOnceSchedule`, `useUpdateOnceSchedule` on the new tRPC procedures; invalidate the same queries the rrule mutations do.
2. **Derived state** — a pure helper in `modules/schedules/lib/` (e.g. `once-state.ts`): `onceState(schedule) → "pending" | "delivering" | "completed" | "missed" | "failed"` per the README rules, plus `isUpcoming(schedule)` (recurring enabled, or once pending/delivering). Use it everywhere below; do not re-derive inline.
3. **Format & lock** — `lib/schedule-format.ts` `scheduleCadenceText` (l.26-30): once → "Once · Mon 28 Sep, 08:30 (Europe/Prague)"; `lastRunStatus` (l.37-48) recognises `delivering`/`missed`. `lib/schedule-lock.ts` (l.5-9): once is not "legacy-cron"; a fired once is read-only.
4. **Form** — `forms/schedule-form-schema.ts`: add a top-level `repeat: "repeat" | "once"` discriminator with `once: { when: "now" | "at", date, time, timezone }` (timezone default from the browser); `forms/schedule-form-modal.tsx`: submit once through the new mutation; `forms/schedule-fields.tsx`: a Repeat/Once segmented control above `ScheduleRecurrenceFields` (l.115); with Once, hide recurrence, session-type (l.280), precheck (l.341) and quiet-hours fields. Editing a pending once opens the form in Once mode; the Repeat/Once switch is disabled when editing (type is fixed after create).
5. **List** — `components/schedules-panel.tsx`: render upcoming schedules first; completed once schedules in a collapsed **Past** section (newest first) showing moment, outcome badge (`completed` / `missed` / `failed`), creator, and a link to the Session. `components/schedule-card.tsx`: hide the enable `Switch` (l.137) for once; show "already on its way" while `delivering`; `components/schedule-details.tsx` (l.31-34, 76-80): once wording instead of "Paused"/next run.
6. **Session link** — the schedule results modal (`components/schedule-results-modal.tsx`) already lists Sessions for a schedule; confirm it finds `schedule_once` Sessions by `scheduleId` and link the Past row to it (the one Session a once opens).
7. **Hard-stop warning** — `modules/agents/hooks/use-sandbox-row-actions.tsx` (l.14-31) and `modules/sandboxes/components/sandbox-home-header.tsx` (l.46-60) count all schedules; count only `isUpcoming` ones. `use-active-schedule-counts.ts` and `use-section-summaries.ts` (l.151-156) count enabled — exclude completed once schedules so "N Schedules running" stays honest.

## Acceptance criteria

- [ ] Creating Once → Now fires immediately; Once → a date/time stores the right instant for the chosen timezone.
- [ ] Once hides recurrence, session-type, precheck and quiet-hours fields; editing a pending once works, a fired once has no edit/toggle control.
- [ ] Completed once schedules appear only under a collapsed Past section, with outcome and a working Session link; `delivering` and `missed` render distinctly.
- [ ] The hard-stop dialog and "N Schedules running" count only schedules that will still fire.
- [ ] Brand is not hardcoded; `mise run //packages/ui:check` and `mise run //packages/ui:test` green.
