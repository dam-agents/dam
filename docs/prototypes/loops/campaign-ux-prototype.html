Findings
Curated findings for this lineage · updated iteration 3
What works

A single idempotency table keyed by request id, written once per charge. Return the stored result on repeat.

Pitfalls found
  • The existence check must run inside the row lock, or concurrent retries both pass it and double-charge. iteration 1
  • Wrapping the whole handler in one transaction stretches the DB call past the timeout budget and breaks test_checkout_timeout. iteration 2
Open question

Where to place the lock so it's correct under concurrency without regressing the timeout test. Iteration 3 tries a narrow lock on just the idempotency row.
