# Supply-chain security

Last verified: 2026-09-25

| Dependency type | CVE defense | Zero-day defense |
|---|---|---|
| **npm (pnpm)** | **Mend SCA** via `cd.yml` — scans lockfile for transitive CVEs, auto-files GitHub issues. **Dependabot** — direct-dep advisories, auto-files PRs. **pnpm audit** — `cd.yml` runs it on `main` pushes and daily, checking the npm advisory database. Remediation: transitive → scoped `pnpm.overrides`; direct → bump in workspace `package.json`. | Lockfile pins exact versions (`--frozen-lockfile` in CI). `minimumReleaseAge` (7 days) blocks freshly-published packages. `trustPolicy: no-downgrade` blocks rollbacks to less-trusted versions. `allowBuilds` allowlist restricts which packages may run postinstall scripts. `check:lockfile-age` mise task enforces the 7-day policy independently of pnpm. |
| **Go modules** | **Mend SCA** via `cd.yml` — covers Go lockfiles. **Dependabot** — configured for `/packages/controller`. **govulncheck** — `cd.yml` runs it on `main` pushes and daily, checking the compiled call graph against the Go vuln DB. Remediation: bump `go.mod` + `go mod tidy`. | Pinned by `go.sum` checksum database. Go module proxy verifies checksums against the public sumdb. |
| **Rust crates** (the vm-runner) | **cargo audit** — `cd.yml` runs it on `main` pushes and daily, checking `Cargo.lock` against the RustSec advisory database. Vulnerabilities only; unmaintained and unsound notices are not filed. smolvm is a path dependency, so its own dependencies are in the same lockfile and are scanned with the crate's. Remediation: bump the requirement in `Cargo.toml` and run `mise run //packages/vm-runner:fix:lock`. | `Cargo.lock` pins exact versions with checksums; every cargo task builds `--locked`. smolvm is cloned at the commit `smolvm.pin` names, and the clone is refused if its tag has moved. |
| **Container base images** | **Trivy** — `cd.yml`'s `container-scan` job scans every published image (`image:resolve list-components`) at the `<commit-sha>` tag the workflow gave it for the current commit (`ignore-unfixed` via `trivy.yaml`, so only findings with an available fix are reported; there is no local scan task (every build publishes a `<sha>` tag — amd64-only except `v*` release builds, which are multi-arch; a PR tags nothing: e2e builds the images it runs on its own runner, and the rest (agents, vm-runner) are built without being published; on `main`/`v*` pushes the same build additionally gets the semver/`latest` release tags; a controller, ui, api-server, keycloak or vm-runner image whose source did not move is not rebuilt on a `main` push but tagged with the commit, and scanned; agent and workload images reused unchanged carry no `<sha>` tag and skip that run's scan — the nightly scheduled run rebuilds and scans every image) — and auto-files one GitHub issue per CVE. Remediation: bump the base/deps, rebuild and push. Findings whose fix exists upstream but isn't in a consumable release yet are **left as open issues, not suppressed** — label them `blocked-upstream` (`gh issue edit <n> --add-label blocked-upstream`); the gate stays red until the bump lands. | Red Hat Hardened Images (HI, `registry.access.redhat.com/hi/`) pinned by tag and digest, so a rebuild never picks up a base update silently: the nightly run keeps a "Base image pins are behind" issue open while a tag has moved past its pin, and `image:bump-bases` re-pins; the agent and VM runner images build on Debian trixie-slim through `mirror.gcr.io`. Keycloak pinned by digest. `gh` built from source with a pinned Go toolchain + bumped `in-toto` (its release binaries lag both the Go security line and that dep). Images sourced from trusted registries (Red Hat, Quay.io). |
| **Third-party container runtime images** | **Not scanned by us.** [Red Hat Hardened Images](https://images.redhat.com/) used wherever possible (`postgresql`, `valkey`, `curl`). Envoy proxy uses an official distroless image. Some utility-only images are from other sources (`quay.io/adorsys/keycloak-config-cli`, `alpine/k8s`). | Tag-pinned in `values.yaml`. Sourced from trusted registries (Red Hat, `registry.k8s.io`). Manual bump only. The subset we serve from our own registry is registered in `.mise/tasks/image/mirror`; `cd.yml`'s `mirror-images` job copies any tag not yet on the mirror on every `main` push, and never overwrites one that is (upstream moves tags; a mirrored tag stays the reviewed image). |
| **The VM runner's hypervisor stack** | **Trivy**, as for every published image — the vm-runner image is in `image:resolve list-components`. | The smolvm release is fetched at image build and refused unless it has the digest `packages/vm-runner/smolvm.pin` records for its architecture; the crane that replaces the one in its guest rootfs is held to digests the same way. The image bases on Debian trixie-slim through `mirror.gcr.io`, like the agent images, and takes its few system packages from Debian's archive at build time, unpinned. The runner binary is built from source with the repo's pinned Rust toolchain on the build host, against the smolvm tree `smolvm.pin` names by commit; the build fails if the binary needs a newer glibc than the image ships. platform-init, the entrypoint of every machine, is linked statically against the build host's glibc, and the build fails if the result is linked dynamically. The KVM device plugin (`ghcr.io/squat/generic-device-plugin`) is pinned **by digest**, which is the right posture for the one privileged DaemonSet with the host's `/dev`. |
| **GitHub Actions** | **Dependabot** — configured for `github-actions` ecosystem, weekly. Auto-files PRs for advisory-affected actions. | Pinned by full commit SHA with version comment (e.g. `actions/checkout@<sha> # v6.0.2`). Tag-only references not used — immune to tag rewriting. |
| **mise dev tools** | **Not scanned.** At time of writing, Dependabot and Mend both have open tickets for adding support. | `mise.lock` pins resolved versions with per-platform SHA-256 checksums. |
