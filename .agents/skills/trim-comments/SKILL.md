# Trim Comments

Long comments rot: they drift from the code, cost tokens on every read, and assert things that
were true on an earlier branch. This pass deletes them and keeps the few that stop a reader from
breaking something.

**Default action is delete** — a rewrite is the exception, and a rewrite is one line. Zero
comments left in a file is a fine outcome. Never change code in this pass; comments only.

## Scope

- **Files** written or edited this session — you know your own edits. If that set is genuinely
  unclear, establish it yourself: resolve the baseline explicitly and fail loudly rather than
  guessing, and when the best set available is the whole branch rather than the session, say so
  in the report instead of passing it off as the session's.
- **Comments** this session authored or touched, plus any inside a hunk it changed. A violating
  comment elsewhere in the same file is reported, never rewritten — the diff stays reviewable.
- **Out of scope**: docs and markdown, generated files, vendored code, untouched files.

## The test

Without this line, would a competent reader of this code do the wrong thing?

- No → delete it.
- Yes → keep the fact, in one line, describing only the code as it stands.

"It's useful context" is a no. "It explains what the code does" is a no — the code does that.

## Delete

1. **Restatement** — paraphrases the line, signature, or type below it.
2. **Duplication** — the fact is already in a name, type, schema, test name, architecture page,
   or another comment. One fact, one place: where it is enforced.
3. **Within-branch reasoning** — narrates the work instead of the result: "previously", "now",
   "used to", "no longer", "instead of", "this replaces", "moved from", "per review". A comment
   states the current solution and never compares it against a past one.
4. **History pointers** — commit SHAs, PR numbers, branch names, dates, authorship, ADR
   references (forbidden in code by [`CLAUDE.md`](../../../CLAUDE.md)).
5. **Issue numbers** — never in production code. One exception, test files only: a regression
   test may name the issue it locks down when the bug was crucial —
   `// regression: #1234 — restart dropped the SVID`. An upstream link justifying a workaround is
   not an issue number.
6. **Bloat** — comments spanning paragraphs, hedging ("basically", "note that"), tutorials on
   the language or framework, ASCII diagrams, section banners, decorative dividers.
7. **Dead weight** — commented-out code, and TODO/FIXME/XXX markers: this repo files issues
   instead of parking work in comments.
8. **Unverifiable claims** — if you cannot confirm what a comment asserts, delete it or flag it.
   Never restate it, and never write a "why" you cannot see in the code.

## Keep

Only these earn a line, and only when the code cannot carry the fact itself:

- **Non-obvious why** — a constraint that returns as a bug if someone "cleans it up": required
  ordering, a race, idempotency, a third-party or protocol quirk. State the consequence.
- **Doubt at the call site** — code that looks wrong but is right.
- **Facts a type cannot state** — units, ranges, invariants, "caller holds the lock".
- **External anchors** — the upstream bug, spec section, or RFC a workaround depends on.
- **Required API docs** — where a language convention or lint rule demands one on an exported
  symbol. Still one line.

## Never touch

Directives, not comments — leave them byte-for-byte: license headers, shebangs, `//go:generate`
and other pragmas, `// nolint`, `// eslint-disable*`, `// biome-ignore`, `// @ts-expect-error`,
`// prettier-ignore`, codegen markers (`Code generated by … DO NOT EDIT.`), and YAML or Helm
template directives.

## Style for the ones that stay

- **One line**, with one release valve: a crucial fact that genuinely will not fit keeps its
  longer comment, flagged in the report. Terseness never costs information — never drop a
  load-bearing fact to satisfy the cap.
- **Lead with the fact.** No preamble, no restating the subject.
- **Present tense, current state.** No comparatives, no history, no plans.
- **Terse and concrete.** Plain words over jargon; name the actual failure or constraint.
- **No new comments.** This is a cutting pass.

```go
// before: We used to look this up on every reconcile, which was slow, so now we cache the
// waypoint address on the status. See PR #3012 for the discussion. This matters because
// the reconcile loop runs often.
// after:
// Cached on status: reconcile runs per pod event and the lookup is a cluster round-trip.
```

```ts
// before: This must be awaited before the next call, otherwise things can break in weird ways
// after:
// Sequential: the broker rejects overlapping publishes on one connection.
```

## Process

1. **Read each edited file in full.** Duplication is invisible from a diff alone.
2. **Classify** every in-scope comment: delete, one-line rewrite, keep verbatim.
3. **Apply** with Edit. Leave no orphan blank lines, dangling `/*`, or empty doc blocks.
4. **Verify.** `mise run check`, then confirm the diff is comment-only — no statement changed.

## Report

- One line per file: comments removed / rewritten / kept.
- **Kept** — each surviving comment with the one-line reason it earns its place, calling out any
  that needed more than one line.
- **Doc gaps** — subsystem behavior a deleted comment explained that no architecture page
  covers. Reported, never written: this skill does not edit docs.
- **Out-of-scope violations** — offered as optional follow-up, never fixed unilaterally.
